# PPT Ultra Profile 设计草案

状态：待评审。目标宿主为 DeepSeek Harness Desktop 的 Web 客户端。

[查看满屏工作台设计稿](profile-mockup.svg)

## 产品目标

打开现有 PPTX，通过自然语言或参数面板调整具体页面和对象，预览后应用修改，交付仍可在 PowerPoint 中继续编辑的文件。首版聚焦缩短标题、对齐图片和替换素材等高频微调。

## 工作台布局

在 DSH 新建会话时选择「PPT 编辑」预设即进入该模式，工作台自动打开（每个会话一次）；其他会话可从会话顶栏「打开 PPT Ultra」手动进入。工作台占满可用视口，顶栏只保留文稿名、当前操作状态和导出入口。界面使用「有待应用修改」「可导出」等状态提示。

| 区域 | 内容与交互 |
| --- | --- |
| 左侧页面导航 | 点击缩略图切换焦点页，标出本轮受影响的页面。 |
| 中央画布 | 默认上方显示「修改前」，下方显示「修改后」。两张画面同宽、同倍率，可同步缩放或切到单页预览。缩放后超出视口时，中央画布独立滚动。修改标注可开关，仅用于预览。 |
| 右侧编辑面板 | 分为「编辑」「变更记录」「检查」。中段独立滚动，底部操作区固定，应用和取消随时可达。 |

「修改前」以本轮开始时的文稿状态为基准，首轮即原稿。「修改后」在应用前显示带标注的预览，应用成功后显示已检查的结果。本轮对照保留到下一轮，方便在提交后复核。窄窗口默认切为单页前后切换，按需展开编辑面板。

## 编辑面板

| 分区 | 交互 |
| --- | --- |
| 编辑范围 | 显示当前页与选中对象。支持从修改后画布点选或在对象列表中多选。每条已加入的操作显式绑定目标，切换选区时仍显示它原有的目标。 |
| 待应用操作 | 自然语言先生成操作清单。每条操作都显示类型、目标和可编辑参数。例如「替换文字」显示新文本，「对齐对象」显示对齐方式和基准对象。可手动添加、移除操作，参数更新后重新生成预览。 |
| 检查 | 应用前显示目标定位和预览检查。应用时复核文件结构和实际渲染。「检查」页签显示具体结果，点问题条目定位对应页和对象。 |
| 变更记录 | 按轮显示已应用的操作及影响页。点记录可查看详情并定位对象。撤销当前轮时恢复上一份通过检查的草稿。 |
| 底部操作区 | 「更新操作」用补充指令修订待应用清单。点「应用修改」提交整批操作，或点「取消待应用修改」清空本轮提案。应用并通过检查后开放导出。 |

设计稿展示应用前状态。用户选中第 7 页，输入「标题短一点，右边两张图顶端对齐」。系统给出两条可编辑的操作，并在下方预览中标出标题和两张图。用户可直接改标题文本，或在下拉框里将对齐基准从左图换到右图，再一次性应用。

| 状态 | 界面行为 |
| --- | --- |
| 未导入 / 读取中 | 提供选择 PPTX 的入口。读取后显示页数、当前页及可操作对象。 |
| 目标不明确 | 列出候选页或对象，待用户点选后生成待应用操作。 |
| 应用中 | 显示当前步骤，暂时锁定待应用操作，原稿和预览仍可查看。 |
| 冲突或校验失败 | 保留上一份通过检查的草稿，指出具体对象和原因。外部文件发生变化时先重新读取。渲染失败时显示「视觉检查未完成」。 |

## Profile、Preset 与 Bundle

- **Profile `ppt-ultra`** 组合 DSH 基础能力和 PPT Bundle，提供工作台入口、PPTX 编辑工具、渲染和文件交付。
- **Preset `ppt-edit`** 约定按页、按对象编辑，沿用原稿样式。用户指令与参数输入都生成可检查的操作清单。
- **Bundle `dsh-ppt-ultra`** 负责界面、结构化编辑和验证。Client 管理当前页、选区和对照。Host 管理权限、文件副本、内部状态与执行。仓库里的 `side-chat` 和 `inner-chrome` 可作为侧栏接入参考。满屏工作台的具体挂载位置需要用目标 DSH 验证。

执行后端先用官方 `office-pptx` 和 `office-render` 做基线，用相同样稿评估 OfficeCLI 的对象编辑与保真表现。Agent 通过受限工具提交指令，Host 校验并执行写入。[DSH Office 技能](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/skill-office/README.md) · [DSH Profile 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)

## 编辑与校验规则

1. **定位。** 使用稳定的页面和对象 ID，界面用页码与对象名称展示。写入请求附内部基准状态标识和目标当前值，防止提交过时的操作。
2. **执行。** 首版支持改文字、换图、对齐、等距和改尺寸。保留原稿，每轮先写临时副本，整批通过检查后才替换当前草稿。基准变化时拒绝写入。
3. **校验。** 重开 PPTX，核对目标属性、页数和受保护部件。对未触及的页面和关键部件做结构对比。用同一渲染器生成目标页前后图，检查溢出、遮挡、裁切和缺字体。
4. **交付。** 导出通过检查的草稿和简短变更清单。SmartArt、动画和原生图表作为首版保真测试对象，具体可编辑范围按实测结果开放。

## 首版验收

| 用例 | 通过条件 |
| --- | --- |
| 打开文稿并上下对照 | 工作台铺满可用视口，两张画面尺寸一致，放大后仍能滚动查看。 |
| 缩短标题并对齐两张图片 | 可在面板里改文本或对齐基准，预览随之更新。应用后仅目标对象变化，标题仍为可编辑文字。 |
| 含混排文字、图表、备注、母版或动画的文稿 | 在 PowerPoint 中重开交付文件，核对与指令无关的样式和复杂对象。 |
| 目标歧义、冲突或校验失败 | 界面给出可定位的原因，原稿和上一份通过检查的草稿可恢复。 |
| 连续两轮微调再撤销 | 恢复上一轮通过检查的结果，预览与导出内容一致。 |

设计稿中的文稿、对象和检查结果均为交互示例。独立画布编辑、模板生成和复杂对象编辑列入后续范围。
