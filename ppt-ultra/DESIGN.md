# PPT Ultra Profile 设计草案

状态：待评审。目标宿主为 DeepSeek Harness Desktop 的 Web 客户端。

[查看满屏工作台设计稿](profile-mockup.svg)

## 产品目标

打开现有 PPTX，通过自然语言或参数面板调整具体页面和对象，预览后应用修改，交付仍可在 PowerPoint 中继续编辑的文件。首版聚焦缩短标题、对齐图片和替换素材等高频微调。

## 工作台布局

工作台是 DSH 根级页面（`main` keyed 面板），入口是左侧栏常驻的「PPT 工作台」行，不依赖 Agent 预设或新建会话：点一次即进入；在工作台内选择/拖入 PPTX，或让 Agent 用 `ppt_ultra_open` 打开文稿后，界面自动切到该页面。工作台占满 DSH 主面板（左侧栏保留，可收起），顶栏保留文稿名、当前操作状态和导出/退出入口。界面使用「有待应用修改」「可导出」等状态提示。右上角为「导出 PPTX」（有可导出草稿时主按钮，否则灰态并提示原因）与「退出 PPT」（返回对话，文稿与修改保留）。

| 区域 | 内容与交互 |
| --- | --- |
| 左侧页面导航 | 点击缩略图切换焦点页，标出本轮受影响的页面。 |
| 中央画布 | 默认上方显示「修改前」，下方显示「修改后」。两张画面同宽、同倍率，可同步缩放或切到单页预览。缩放后超出视口时，中央画布独立滚动。修改标注可开关，仅用于预览。 |
| 右侧面板 | 只有「文件选择」「对话」两个 tab：选仓库/文件、与绑定会话的 Agent 对话并应用修改。中段独立滚动；窄窗口下作为页面内抽屉。 |

「修改前」以本轮开始时的文稿状态为基准，首轮即原稿。「修改后」在应用前显示带标注的预览，应用成功后显示已检查的结果。本轮对照保留到下一轮，方便在提交后复核。窄窗口默认切为单页前后切换，按需展开右侧面板。

## 右侧面板

### 文件选择

| 区域 | 交互 |
| --- | --- |
| 仓库 | 已注册 DSH 工作区下拉；切换后回到该仓库根目录。 |
| 目录导航 | 面包屑 + 目录行；只显示目录和 .pptx，隐藏以 `.` 开头的项。 |
| 打开 | 点 .pptx 在当前对话打开；勾选「打开时新建对话（独立上下文）」时先新建 DSH 会话，再在该会话打开（已有文稿会重新打开）。 |

### 对话

| 区域 | 交互 |
| --- | --- |
| 会话 | 绑定一个 DSH Session，显示标题；「新建对话」创建新 Session 并切换。不同对话上下文相互独立。 |
| 消息 | 轮询 Host `conversation` 路由，显示人类消息与助手回复；运行中显示流式文本和「正在处理」。 |
| 待应用修改 | Agent 提出操作后显示操作条数、影响页与检查摘要；勾选核对后「应用修改」，也可「取消待应用」；已应用时提供「撤销最近一轮」。 |
| 输入区 | Enter 发送、Shift+Enter 换行；指令携带当前文稿 id/revision、焦点页和选中对象；运行中可停止。 |

画布上仍可点选对象，当前选中对象会带进对话指令。示例：用户打开第 7 页，输入「标题短一点，右边两张图顶端对齐」；Agent 读取文稿后提出两条操作，中间显示带标注的前后预览，对话上方出现待应用卡片，用户核对后一次性应用。

| 状态 | 界面行为 |
| --- | --- |
| 未导入 / 读取中 | 文件选择 tab 浏览仓库；打开后显示页数、当前页；中心显示欢迎/加载态。 |
| 目标不明确 | 工作台显示候选对象，对话中给出澄清问题；点候选可定位到对应页和对象。 |
| 应用中 | 显示当前步骤，暂时锁定应用与导出；原稿和预览仍可查看。 |
| 冲突或校验失败 | 保留上一份通过检查的草稿，指出具体对象和原因。外部文件发生变化时先重新读取。渲染失败时显示「视觉检查未完成」。 |

## Profile、Preset 与 Bundle

- **Profile** 只负责加载 DSH 基础能力和本 Bundle；不再声明 `ppt-edit` 预设，也不提供独立 `ppt-ultra` Profile。
- **Preset** 不参与入口：工作台在任意会话、任意预设下都可用；自然语言微调提交到当前会话。
- **Bundle `dsh-ppt-ultra`** 负责界面、结构化编辑和验证。Client 管理当前页、选区和对照，并把工作台注册为左侧栏入口 + 主区域页面；Host 管理权限、文件副本、内部状态与执行。仓库里的 `side-chat` 和 `inner-chrome` 可作为侧栏接入参考。

执行后端先用官方 `office-pptx` 和 `office-render` 做基线，用相同样稿评估 OfficeCLI 的对象编辑与保真表现。Agent 通过受限工具提交指令，Host 校验并执行写入。[DSH Office 技能](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/skill-office/README.md) · [DSH Profile 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)

## 编辑与校验规则

1. **定位。** 使用稳定的页面和对象 ID，界面用页码与对象名称展示。写入请求附内部基准状态标识和目标当前值，防止提交过时的操作。
2. **执行。** 首版支持改文字、换图、对齐、等距和改尺寸。保留原稿，每轮先写临时副本，整批通过检查后才替换当前草稿。基准变化时拒绝写入。
3. **校验。** 重开 PPTX，核对目标属性、页数和受保护部件。对未触及的页面和关键部件做结构对比。用同一渲染器生成目标页前后图，检查溢出、遮挡、裁切和缺字体。
4. **交付。** 导出通过检查的草稿和简短变更清单。SmartArt、动画和原生图表作为首版保真测试对象，具体可编辑范围按实测结果开放。

## 首版验收

| 用例 | 通过条件 |
| --- | --- |
| 打开文稿并上下对照 | 工作台铺满可用视口，两张画面尺寸一致，放大后仍能滚动查看。 |
| 缩短标题并对齐两张图片 | 在「对话」里用一句话描述，Agent 生成操作与预览；勾选核对后应用。应用后仅目标对象变化，标题仍为可编辑文字。 |
| 含混排文字、图表、备注、母版或动画的文稿 | 在 PowerPoint 中重开交付文件，核对与指令无关的样式和复杂对象。 |
| 目标歧义、冲突或校验失败 | 界面给出可定位的原因，原稿和上一份通过检查的草稿可恢复。 |
| 连续两轮微调再撤销 | 恢复上一轮通过检查的结果，预览与导出内容一致。 |

设计稿中的文稿、对象和检查结果均为交互示例。独立画布编辑、模板生成和复杂对象编辑列入后续范围。
